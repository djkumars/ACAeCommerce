# Integration hand-off checklist

- Backend: `services/ProductCatalog`, `services/Inventory`, `services/Order`, `services/Payment`; run `docker compose up --build` from workspace root; host ports `5081`–`5084`, container port `8080`; health `GET /health`; build `dotnet build ACAECommerce.slnx`.
- Frontend: `services/web`; install `npm --prefix services/web install`; dev `npm --prefix services/web start`; build `npm --prefix services/web run build`; live API seam `src/api/index.ts` (configured by `src/app/environment.ts` and runtime `config.js`); no mock frontend client or dev-only switcher is present.
- Current demo state requiring replacement: catalog and inventory in-memory data in `services/ProductCatalog/Program.cs` and `services/Inventory/Program.cs`; orders in `services/Order/Program.cs`; payment attempts are not persisted.
- API routes: Catalog `GET /health`, `GET /api/products`, `GET /api/products/{id}`; Inventory `GET /health`, `GET /api/inventory/{productId}`, `POST /api/inventory/reservations`, `POST /api/inventory/release`; Order `GET /health`, `GET /api/orders/{id}`, `POST /api/orders`; Payment `GET /health`, `POST /api/payments/authorize`.
- Database: Azure SQL; dedicated `CatalogDb`, `InventoryDb`, `OrdersDb`, `PaymentsDb`; SQL DDL under each service `database/`; no ORM/migration runner is wired yet. Implement migration history and an automated runner as needed; **do not add seed data**. Connection configuration should use separate least-privilege managed identities/credentials per service and private networking.
- Shared types: none yet; DTOs are local to services and storefront API types are in `services/web/src/api/index.ts`. Consider a typed shared contract package only if service API contracts need code generation; do not couple persistence models to public DTOs.
- Services: Angular storefront (Essential); Catalog, Inventory, Order, sandbox Payment APIs (Essential); Azure SQL schemas and Bicep platform (Essential); durable storage, authentication, payment provider integration, and production load certification (Enhancement/out of scope).
- Safety: mock/sandbox payment only; never collect or persist card data. SQL scripts are schema-only and must contain no seed data.
